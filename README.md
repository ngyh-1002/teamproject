# 🗺️ ROS Map Configuration (`map.yaml`) 설명

이 문서는 ROS(로봇 운영체제)에서 사용하는 **맵 설정 파일(`map.yaml`)**의 구조와 좌표계 개념을 설명합니다.  
이 파일은 `.pgm` 형태의 **지도 이미지(map.pgm)** 와 함께 사용되며,  
픽셀 단위의 이미지를 실제 **월드 좌표계(미터 단위)**로 변환하는 데 필요한 정보를 담고 있습니다.

---

## 📁 예시 코드

```yaml
image: map.pgm
resolution: 0.050000
origin: [-6.828606, -9.466283, 0.000000]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.196
````

---

## 📖 항목별 설명

### 🖼️ `image: map.pgm`

* 지도 데이터가 저장된 **이미지 파일 경로**
* 일반적으로 흑백 이미지이며:

  * **검은색(0)** → 장애물(Occupied)
  * **하얀색(255)** → 빈 공간(Free)
  * **회색** → 미확인 영역(Unknown)

---

### 📏 `resolution: 0.050000`

* 한 **픽셀이 실제 거리로 몇 미터인지**를 의미합니다.
* `0.05` → 1픽셀 = 0.05m (5cm)
* 즉, 지도의 해상도를 나타냅니다.

---

### 📍 `origin: [-6.828606, -9.466283, 0.000000]`

* 맵의 **좌하단(왼쪽 아래) 픽셀**이 실제 좌표계 상에서 어디에 위치하는지를 나타냅니다.
* 형식: `[x, y, yaw]`

  * `x`: 원점의 X 좌표 (미터)
  * `y`: 원점의 Y 좌표 (미터)
  * `yaw`: 회전 각도 (라디안 단위, 일반적으로 0)

> 예시: 맵의 좌하단 픽셀(이미지의 (0, height))은 실제 월드 좌표계의 `(-6.83m, -9.47m)` 지점에 해당합니다.

---

### ⚫ `negate: 0`

* 흑백 반전 여부 설정

  * `0`: 검은색 = 장애물
  * `1`: 반전 (검은색 = 빈공간)
* 대부분의 경우 `0`이 기본값입니다.

---

### 🧱 `occupied_thresh: 0.65`

* 픽셀 값이 **0.65 이상**일 경우 장애물(Occupied)로 인식합니다.
* 즉, 65% 이상 검은색이면 벽으로 판단합니다.

---

### ⚪ `free_thresh: 0.196`

* 픽셀 값이 **0.196 이하**일 경우 빈 공간(Free)으로 인식합니다.
* 즉, 19.6% 이하 검은색이면 통로로 판단합니다.

---

## 📚 정리표

| 항목                | 의미                   | 예시 값                  | 설명                |
| ----------------- | -------------------- | --------------------- | ----------------- |
| `image`           | 맵 이미지 파일             | `map.pgm`             | 흑백 지도 이미지         |
| `resolution`      | 해상도 (픽셀당 미터)         | `0.05`                | 1픽셀 = 5cm         |
| `origin`          | 지도 시작 위치 (x, y, yaw) | `[-6.83, -9.47, 0.0]` | 맵의 좌하단 픽셀의 실제 좌표  |
| `negate`          | 색 반전 여부              | `0`                   | 0 = 검은색이 장애물      |
| `occupied_thresh` | 장애물 임계값              | `0.65`                | 65% 이상 검은색 = 벽    |
| `free_thresh`     | 빈공간 임계값              | `0.196`               | 19.6% 이하 검은색 = 통로 |

## 🔄 이미지 맵과 ROS 맵 좌표계 차이

ROS에서 사용하는 맵은 **이미지(map.pgm)** 와 좌표계 방향이 다르기 때문에
**상하반전 관계**로 보일 수 있습니다.

| 구분                   | X축 방향 | Y축 방향 | 원점 위치 |
| -------------------- | ----- | ----- | ----- |
| 🖼️ 이미지(map.pgm)     | 오른쪽   | 아래쪽   | 좌측 상단 |
| 🗺️ ROS 맵(map frame) | 오른쪽   | 위쪽    | 좌측 하단 |

즉, ROS는 이미지를 불러올 때 내부적으로 **상하반전(Flip Vertically)** 을 적용하여
맵 좌표계의 방향을 맞춥니다.

---

### 🧭 시각적 비교 (개념도)

```
이미지 좌표 (map.pgm)
(0,0)
  ┌───────────────────────────────→ x+
  │
  │
  ↓ y+
(0,height) ← 이 픽셀이 ROS에서의 origin에 해당

ROS 좌표계 (map frame)
(origin_x, origin_y)
  ↑ y+
  │
  │
  └──────────────────────────────→ x+
```

즉,

* 이미지의 (0,0)은 **좌측 상단**
* ROS의 (0,0)은 **좌측 하단**
* 따라서 ROS에서 맵을 표시하면 이미지가 **상하반전되어 나타나는 것처럼 보이는 것이 정상**입니다.

---

## 🧩 좌우반전 여부

* 좌우반전 ❌ **없음**
  (x축 방향은 이미지와 ROS 둘 다 오른쪽이 + 방향)
* 상하반전 ✅ **있음**
  (이미지는 아래로 y+, ROS는 위로 y+)

## 🧭 정리 한 줄

> ✅ ROS 맵(`map.yaml`)은 이미지의 **좌하단 픽셀**을 기준으로 좌표계를 설정하며,
> 내부적으로 **상하반전된 좌표계**를 사용한다.
> 이는 정상적인 ROS 좌표계 처리 방식이다.

## 🧩 ROS 2 원격 PC 환경 설정 (.bashrc)

원격 PC에서 라즈베리파이(로봇 본체)로부터 ROS 2 노드를 수신하고 통신하기 위해서는 ROS 2 환경 변수를 올바르게 설정해야 합니다.
아래 설정들은 `.bashrc` 파일에 추가하면, 터미널을 새로 열 때마다 자동으로 적용됩니다.

---

### 📄 설정 방법

```bash
gedit ~/.bashrc
```

파일 맨 아래에 아래 내용을 추가한 뒤 저장하고 닫습니다.
그 후 다음 명령으로 적용합니다:

```bash
source ~/.bashrc
```

---

### ⚙️ 설정 내용

```bash
export RPLIDAR_MODEL=A1
export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
```

---

### 🧠 각 명령어 설명

| 명령어                                          | 역할 설명                                                                                                                                         |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `export RPLIDAR_MODEL=A1`                    | **RPLIDAR 모델 지정**<br>라이다 드라이버 패키지가 어떤 모델(A1, A2, A3 등)을 사용하는지 구분하기 위한 환경 변수입니다. launch 파일에서 자동으로 참조될 수 있습니다.                                  |
| `export ROS_DOMAIN_ID=30`                    | **ROS 2 네트워크 구분용 ID 설정**<br>같은 LAN 상에 여러 ROS 네트워크가 존재할 때, 서로 다른 Domain ID를 주어 충돌을 방지합니다.<br>라즈베리파이와 원격 PC는 반드시 **같은 Domain ID**여야 통신이 가능합니다.  |
| `export ROS_LOCALHOST_ONLY=0`                | **네트워크 통신 활성화**<br>`1`이면 로컬호스트(127.0.0.1) 통신만 허용하고, `0`이면 LAN을 통한 다른 장치와의 통신을 허용합니다.<br>원격 통신을 위해 반드시 `0`으로 설정해야 합니다.                         |
| `export RMW_IMPLEMENTATION=rmw_fastrtps_cpp` | **ROS 미들웨어 구현체 선택**<br>ROS 2는 DDS 통신을 위해 다양한 RMW를 지원합니다. FastDDS(FastRTPS)는 기본적이고 안정적인 선택입니다.<br>통신 호환성을 위해 라즈베리파이와 원격 PC 모두 같은 설정을 유지해야 합니다. |
| `source /opt/ros/humble/setup.bash`          | **ROS 2 기본 환경 로드**<br>ROS 2 Humble이 설치된 시스템 경로를 불러와 명령어(`ros2`, `colcon`, `rviz2` 등)를 사용할 수 있게 합니다.                                           |
| `source ~/ros2_ws/install/setup.bash`        | **사용자 워크스페이스 환경 로드**<br>사용자가 직접 빌드한 패키지(예: `scout_mini`, `rplidar_ros`, `nav2` 등)를 ROS 2 환경에 등록하여 인식시킵니다.                                     |
