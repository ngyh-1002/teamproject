# 🗺️ ROS Map Configuration (`map.yaml`) 설명

이 문서는 ROS(로봇 운영체제)에서 사용하는 **맵 설정 파일(`map.yaml`)**의 구조와 좌표계 개념을 설명합니다.  
이 파일은 `.pgm` 형태의 **지도 이미지(map.pgm)** 와 함께 사용되며,  
픽셀 단위의 이미지를 실제 **월드 좌표계(미터 단위)**로 변환하는 데 필요한 정보를 담고 있습니다.

---

## 📁 예시 코드

```yaml
image: map.pgm
resolution: 0.050000
origin: [-6.828606, -9.466283, 0.000000]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.196
````

---

## 📖 항목별 설명

### 🖼️ `image: map.pgm`

* 지도 데이터가 저장된 **이미지 파일 경로**
* 일반적으로 흑백 이미지이며:

  * **검은색(0)** → 장애물(Occupied)
  * **하얀색(255)** → 빈 공간(Free)
  * **회색** → 미확인 영역(Unknown)

---

### 📏 `resolution: 0.050000`

* 한 **픽셀이 실제 거리로 몇 미터인지**를 의미합니다.
* `0.05` → 1픽셀 = 0.05m (5cm)
* 즉, 지도의 해상도를 나타냅니다.

---

### 📍 `origin: [-6.828606, -9.466283, 0.000000]`

* 맵의 **좌하단(왼쪽 아래) 픽셀**이 실제 좌표계 상에서 어디에 위치하는지를 나타냅니다.
* 형식: `[x, y, yaw]`

  * `x`: 원점의 X 좌표 (미터)
  * `y`: 원점의 Y 좌표 (미터)
  * `yaw`: 회전 각도 (라디안 단위, 일반적으로 0)

> 예시: 맵의 좌하단 픽셀(이미지의 (0, height))은 실제 월드 좌표계의 `(-6.83m, -9.47m)` 지점에 해당합니다.

---

### ⚫ `negate: 0`

* 흑백 반전 여부 설정

  * `0`: 검은색 = 장애물
  * `1`: 반전 (검은색 = 빈공간)
* 대부분의 경우 `0`이 기본값입니다.

---

### 🧱 `occupied_thresh: 0.65`

* 픽셀 값이 **0.65 이상**일 경우 장애물(Occupied)로 인식합니다.
* 즉, 65% 이상 검은색이면 벽으로 판단합니다.

---

### ⚪ `free_thresh: 0.196`

* 픽셀 값이 **0.196 이하**일 경우 빈 공간(Free)으로 인식합니다.
* 즉, 19.6% 이하 검은색이면 통로로 판단합니다.

---

## 📚 정리표

| 항목                | 의미                   | 예시 값                  | 설명                |
| ----------------- | -------------------- | --------------------- | ----------------- |
| `image`           | 맵 이미지 파일             | `map.pgm`             | 흑백 지도 이미지         |
| `resolution`      | 해상도 (픽셀당 미터)         | `0.05`                | 1픽셀 = 5cm         |
| `origin`          | 지도 시작 위치 (x, y, yaw) | `[-6.83, -9.47, 0.0]` | 맵의 좌하단 픽셀의 실제 좌표  |
| `negate`          | 색 반전 여부              | `0`                   | 0 = 검은색이 장애물      |
| `occupied_thresh` | 장애물 임계값              | `0.65`                | 65% 이상 검은색 = 벽    |
| `free_thresh`     | 빈공간 임계값              | `0.196`               | 19.6% 이하 검은색 = 통로 |

## 🔄 이미지 맵과 ROS 맵 좌표계 차이

ROS에서 사용하는 맵은 **이미지(map.pgm)** 와 좌표계 방향이 다르기 때문에
**상하반전 관계**로 보일 수 있습니다.

| 구분                   | X축 방향 | Y축 방향 | 원점 위치 |
| -------------------- | ----- | ----- | ----- |
| 🖼️ 이미지(map.pgm)     | 오른쪽   | 아래쪽   | 좌측 상단 |
| 🗺️ ROS 맵(map frame) | 오른쪽   | 위쪽    | 좌측 하단 |

즉, ROS는 이미지를 불러올 때 내부적으로 **상하반전(Flip Vertically)** 을 적용하여
맵 좌표계의 방향을 맞춥니다.

---

### 🧭 시각적 비교 (개념도)

```
이미지 좌표 (map.pgm)
(0,0)
  ┌───────────────────────────────→ x+
  │
  │
  ↓ y+
(0,height) ← 이 픽셀이 ROS에서의 origin에 해당

ROS 좌표계 (map frame)
(origin_x, origin_y)
  ↑ y+
  │
  │
  └──────────────────────────────→ x+
```

즉,

* 이미지의 (0,0)은 **좌측 상단**
* ROS의 (0,0)은 **좌측 하단**
* 따라서 ROS에서 맵을 표시하면 이미지가 **상하반전되어 나타나는 것처럼 보이는 것이 정상**입니다.

---

## 🧩 좌우반전 여부

* 좌우반전 ❌ **없음**
  (x축 방향은 이미지와 ROS 둘 다 오른쪽이 + 방향)
* 상하반전 ✅ **있음**
  (이미지는 아래로 y+, ROS는 위로 y+)

---

## 🧭 정리 한 줄

> ✅ ROS 맵(`map.yaml`)은 이미지의 **좌하단 픽셀**을 기준으로 좌표계를 설정하며,
> 내부적으로 **상하반전된 좌표계**를 사용한다.
> 이는 정상적인 ROS 좌표계 처리 방식이다.
